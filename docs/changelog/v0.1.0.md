# v0.1.0-next

::: callout warning Prerelease
This release is still in development and has not been tagged yet.
:::

v0.0.1 was a prototype. This is the first release of Zirric as it is meant to be written: explicit mutability, one function syntax, type hints that are checked, and a standard library written in Zirric itself. Nothing is carried over, so there is no migration — read this as the starting point rather than as a list of changes.

## Implemented Proposals

- [ZE-001 Base Language](/proposals/ZE-001-base-language) — declarations, expressions, operators, control flow, modules, imports, literals and attributes.
- [ZE-002 The Cavefile](/proposals/ZE-002-the-cavefile) — the package manifest: dependencies through `cave`, and tasks through `tasks`, wired into `zirric task`.
- [ZE-008 Error Handling](/proposals/ZE-008-error-handling) — `Result` and `@AnyResult` for APIs that can fail.
- [ZE-009 Option Values](/proposals/ZE-009-option-values) — `Option` for values that may be absent.
- [ZE-010 Iterable](/proposals/ZE-010-iterable) — `for element <- value` over anything carrying `@Iterable`, with `@Countable`, `Range` and `Pair`.
- [ZE-013 Mutability and Constants](/proposals/ZE-013-mutability-and-constants) — `const` and `var` in place of `let`.
- [ZE-014 Attribute and Declaration Keywords](/proposals/ZE-014-attribute-and-declaration-keywords) — the `attr` keyword, and parentheses on every attribute.
- [ZE-016 Unified Function and Closure Syntax](/proposals/ZE-016-closure-syntax) — `fn(params) { body }` for both named functions and closures.
- [ZE-017 Type Hints and Type Matching](/proposals/ZE-017-type-hints) — `: T` and `-> T`, composite type expressions, `is` and `switch` on types.
- [ZE-018 I/O, Formatting, and OS](/proposals/ZE-018-io-fmt-os) — the `io`, `fmt` and `os` modules.
- [ZE-021 Encoding and Decoding](/proposals/ZE-021-encoding-and-decoding) — `coding`, `json` and `yaml` over a native value tree.
- [ZE-022 Static Checks](/proposals/ZE-022-static-checks) — analysis reports the mistakes it is certain about, including type hints that do not hold.
- [ZE-023 Code Formatting](/proposals/ZE-023-code-formatting) — a canonical layout written by `zirric fmt`.
- [ZE-024 Qualified Module Names](/proposals/ZE-024-qualified-module-names) — every source file names the module it belongs to, by its fully qualified path, under the base its `Cavefile` declares.

## Notable Changes

- Documentation comments are part of the language. The comments above a declaration, above a field, and above each of a module's `mod` declarations are kept by the compiler and read back with `reflect.docs`. See [Declarations § Documentation comments](/specification/declarations#documentation-comments).
- `reflect` describes a module as it was declared, not only as it ended up: `reflect.moduleOf` answers with its documentation, what it imports, the files it was read from, and every public declaration — including a `const`, whose exported value carries none of that.
- Attributes written on a `mod` declaration reach the module value, so `@Attr()` above `mod` is read back off the module exactly as off any other value.
- A `Cavefile` declares its package's base module path with its own `mod`, which is also where the package takes its name from, and `@cave.Dependencies()` is now `@cave.Package()`. The same declaration describes the package as well: `@cave.Git` on it is the package's repository, and `@cave.Version` its own version. The `@cave.Package("url")` form on `mod` is gone.
- New `cave` attributes describe a package and its dependencies alike: `@cave.Description(desc)`, `@cave.Documentation(url)` and `@cave.LanguageVersion(predicate)`. All of them are printed by `zirric cave describe`.
- A `@cave.LanguageVersion` the running Zirric does not satisfy refuses the project: `zirric cave install`, `run`, `fmt` and `task` all stop with it, before any package is fetched or any source is touched. Only `zirric cave describe` still opens such a project, so that the manifest can be read to see why. A development build that carries no version of its own is exempt.
- A script run by path belongs to the module its directory names, rather than to the project root. Its top-level code runs either way.
- A built-in command can call a task of the same name through itself, so a project extends it rather than replacing it. `zirric fmt` formats `.zirr` sources and then runs a declared `fmt` task, passing on the flags it was given — but only when the task declares them, since one that cannot be told to check must not be asked to. It exits zero only when both succeed. `zirric test` takes the other shape: a declared task runs _instead_ of the built-in. More commands will follow.

## Command Line

- The Cavefile commands live under `zirric cave` (aliased `cv`): `zirric cavefile` is `zirric cave describe`, `zirric init` is `zirric cave new`, and `zirric install` is `zirric cave install` — or `zirric cv i`. `zirric cave describe` prints the package under a `package:` key rather than a top-level `name:` and `source:`.
- `zirric cave new` takes `--mod`, `--git-url`, `--version`, `--language-version`, `--description` and `--documentation-url`, and writes the attributes for them. In a Git repository it reads the remote and names the package after it; without one, `--mod` is required, since a package has to be named. `zirric cv n` is the shorthand.
- `zirric task run <name>` is now `zirric task <name>`, and `zirric x` is gone: a task whose name no built-in command claims answers to `zirric <name>` directly. `zirric task` lists tasks in a stable order, aligned in columns.
- `zirric test` runs a declared `test` task, or — when there is none — the standard library's runner over every module whose name ends in `_t`, so a project has a working `zirric test` with nothing declared at all.
- `zirric lint` and `zirric docs` are removed. They did nothing, and the names are now free for tasks of your own.
- `zirric <file>.zirr` runs that file and `zirric <directory>` runs the module that directory holds, so `run` need not be said out loud.
- `zirric -v` is gone; `--version` spells it out. The `-v` slot belongs to verbosity.

## Tooling

- The Zirric Language Server (`zirric lsp`) provides diagnostics, go-to-definition, completions and formatting.
- `zirric fmt` formats `.zirr` sources and `Cavefile`s, with `--check`, `--list`, `--diff` and `--stdin`. See [Code Formatter](/tooling/code-formatter). `--no-excludes` no longer slips past a `@cave.LanguageVersion` the running Zirric does not satisfy; it was the one path that never read the Cavefile.
- `zirric version` (and `zirric --version`) print the version, commit and build date this binary was built from, stamped in through [metal-stack/v](https://github.com/metal-stack/v).
- Errors point at a line and column and print the line with a caret under it; every problem in a file is reported at once, and a failure at runtime says where it happened.
- [Tree-Sitter-Zirric](https://code.knabel.dev/zirric-lang/tree-sitter-zirric) [v0.4.0](https://code.knabel.dev/zirric-lang/tree-sitter-zirric/releases/tag/v0.4.0) for editors. See [Editor Configuration](/tooling/editor-configuration).
- Language documentation at [zirric.knabel.dev](https://zirric.knabel.dev).
