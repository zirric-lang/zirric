# v0.1.0-next

::: callout warning Prerelease
This release is still in development and has not been tagged yet.
:::

This release introduces explicit mutability, a unified function and closure syntax, first-class type hints with `is`/`switch` matching, and dedicated keywords for attributes and declarations. Together these changes significantly reshape the language surface from v0.0.1.

## Breaking Changes

- `module` keyword renamed to `mod`.
- `let` replaced by `const` (immutable) and `var` (mutable). Migrate existing `let` declarations to `const`.
- `func` keyword renamed to `fn`. Closures changed from `func name { args -> body }` and `{ args -> body }` to `fn name(args) { body }` and `fn(args) { body }`.
- A bare `return` followed by a newline and a line starting with an operator is now parsed as a bare return plus a separate statement. Previously the following line was silently absorbed as the return value, because the operator token lost the newline that preceded it. Write the value on the same line as `return`.
- `mod` is now required in every source file and takes the module's fully qualified path, e.g. `mod code.knabel.dev.zirric_lang.ui.flow.node`. The last segment still binds the module locally; `mod local = path` binds something else. See [ZE-024](/proposals/ZE-024-qualified-module-names).
- A `Cavefile` declares its package's base module path with its own `mod`, which is also where the package takes its name from. `zirric cave new` writes one.
- `@cave.Dependencies()` is renamed to `@cave.Package()`. The same declaration now describes the package as well: `@cave.Git` on it is the package's repository, and `@cave.Version` its own version. The `@cave.Package("url")` form on `mod` is gone — use `@cave.Git` instead.
- `zirric cave describe` prints the package under a `package:` key rather than a top-level `name:` and `source:`.
- The Cavefile commands moved under `zirric cave` (aliased `cv`): `zirric cavefile` is now `zirric cave describe`, `zirric init` is `zirric cave new`, and `zirric install` is `zirric cave install` — or `zirric cv i`.
- `zirric task run <name>` is now `zirric task <name>`, and `zirric x` is gone: a task whose name no built-in command claims answers to `zirric <name>` directly.
- `zirric lint` and `zirric docs` are removed. They did nothing, and the names are now free for tasks of your own. `zirric test` stays, and now runs something.
- `zirric -v` is gone; `--version` spells it out. The `-v` slot belongs to verbosity.
- `zirric <file>.zirr` runs that file, so `run` need not be said out loud.
- `zirric cave new` takes `--mod`, `--git-url`, `--version`, `--language-version`, `--description` and `--documentation-url`, and writes the attributes for them. In a Git repository it reads the remote and names the package after it; without one, `--mod` is required, since a package has to be named. `zirric cv n` is the shorthand.
- `zirric test` runs a declared `test` task, or — when there is none — the standard library's runner over every module whose name ends in `_t`, so a project has a working `zirric test` with nothing declared at all.
- `zirric <directory>` runs the module that directory holds, the way `zirric <file>.zirr` runs a file.

## Implemented Proposals

- [ZE-001 Base Language](/proposals/ZE-001-base-language) — Core language: declarations, expressions, operators, control flow, modules, imports, literals, and attributes.
- [ZE-002 The Cavefile](/proposals/ZE-002-the-cavefile) — Package manifest and task runner: `Cavefile` dependency declarations via the `cave` module (`@cave.Package`, stdlib/local/git sources), and `@tasks.Exec`/`@tasks.Call` task declarations with typed flags/args wired into `zirric task` and the top level.
- [ZE-013 Mutability and Constants](/proposals/ZE-013-mutability-and-constants) — Replace `let` with `const` and `var` for explicit mutability. Upvalue-based closure captures.
- [ZE-014 Attribute and Declaration Keywords](/proposals/ZE-014-attribute-and-declaration-keywords) — Dedicated `attr` keyword and mandatory parentheses for attribute application.
- [ZE-016 Unified Function and Closure Syntax](/proposals/ZE-016-closure-syntax) — Closures use `fn(params) { body }`, unifying named and anonymous function syntax.
- [ZE-017 Type Hints and Type Matching](/proposals/ZE-017-type-hints) — First-class type hints (`: T`, `-> T`), composite type expressions (`[T]`, `[K: V]`, `fn() -> R`), `is` type checking, and `switch` type matching.
- [ZE-008 Error Handling](/proposals/ZE-008-error-handling) — Standardized `Result` and `AnyResult` union types for failure-aware APIs in `prelude`.
- [ZE-009 Option Values](/proposals/ZE-009-option-values) — Standard `Optional` type for values that may be present or absent, defined in `prelude`.
- [ZE-018 I/O, Formatting, and OS](/proposals/ZE-018-io-fmt-os) — New `io`, `fmt`, and `os` standard library modules for byte streams, text formatting/printing, and OS interaction (stdout, stdin, stderr, exit, env, args).
- [ZE-010 Iterable](/proposals/ZE-010-iterable) — Custom `for element <- value` using `@Iterable` and adds `Range`, `ClosedRange`, `@Countable`, `Pair` types.
- [ZE-022 Static Checks](/proposals/ZE-022-static-checks) — Analysis reports mistakes it is certain about: undefined names, wrong arity, unsupported operators, unknown fields and members, and values that do not match the types a program declares. Amends ZE-017: a type hint that is written is now checked.
- [ZE-023 Code Formatting](/proposals/ZE-023-code-formatting) — A canonical source layout written by `zirric fmt` and applied by editors on save, with per-project path excludes via `@cave.FormattingExcludes`.
- [ZE-024 Qualified Module Names](/proposals/ZE-024-qualified-module-names) — Every source file names the module it belongs to, by its fully qualified path, under the base its `Cavefile` declares.

## Notable Changes

- New `cave` attributes describe a package and its dependencies alike: `@cave.Description(desc)`, `@cave.Documentation(url)` and `@cave.LanguageVersion(predicate)`. All of them are printed by `zirric cave describe`.
- A `@cave.LanguageVersion` the running Zirric does not satisfy refuses the project: `zirric cave install`, `run`, `fmt` and `task` all stop with it, before any package is fetched or any source is touched. Only `zirric cave describe` still opens such a project, so that the manifest can be read to see why. A development build that carries no version of its own is exempt.
- A script run by path belongs to the module its directory names, rather than to the project root. Its top-level code runs either way.
- A built-in command can call a task of the same name through itself, so a project extends it rather than replacing it. `zirric fmt` formats `.zirr` sources and then runs a declared `fmt` task, passing on the flags it was given — but only when the task declares them, since one that cannot be told to check must not be asked to. It exits zero only when both succeed. `zirric test` takes the other shape: a declared task runs _instead_ of the built-in. More commands will follow.
- `zirric task` lists tasks in a stable order, aligned in columns. They used to come out of a map, so the order differed between runs.

## Diagnostics

- Errors point at a line and column, and the CLI prints the line with a caret under it.
- Every problem in a file is reported at once, rather than one per run.
- A failure at runtime says where it happened and prints the stack that led there.
- Messages name types the way they are written — `String`, not `runtime.String` — and say which value they were given.
- An unclosed bracket is reported where it was opened.

## Bug Fixes

- `zirric fmt --no-excludes` no longer slips past a `@cave.LanguageVersion` the running Zirric does not satisfy. It says nothing about which Zirric may build a package, and was only skipping the check because it was the one path that never read the Cavefile.

- Many compiler, virtual machine, and standard library fixes, most of them surfaced while writing the [ZE-020 Standard Library](/proposals/ZE-020-standard-library) modules in Zirric.
- Comments and whitespace before a delimiter or an operator were discarded by the lexer, so a comment placed before `}`, `)`, `,` or `@` disappeared.
- Two-character operators (`->`, `==`, `!=`, `&&`, `||`, `+=`, and the rest) carried no source position, so features that work from offsets skipped them.
- Comment text lost its `//` or `#` marker and one following space, which mangled `#!` shebang lines and `///` doc comments.
- An unterminated `data`, `union`, `attr`, `extern type` or `import { … }` body made the parser loop forever instead of reporting an error, hanging the language server while such a block was being typed.
- A malformed attribute argument produced a `nil` expression that crashed anything walking the syntax tree.

## Tooling

- Update [Tree-Sitter-Zirric](https://code.knabel.dev/zirric-lang/tree-sitter-zirric) to [v0.4.0](https://code.knabel.dev/zirric-lang/tree-sitter-zirric/releases/tag/v0.4.0) and update your queries as described in [Editor Configuration](/tooling/editor-configuration).

- `zirric version` (and `zirric --version`) print the version, commit and build date this binary was built from, stamped in through [metal-stack/v](https://github.com/metal-stack/v).
