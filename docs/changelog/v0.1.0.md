# v0.1.0-next

::: callout warning Prerelease
This release is still in development and has not been tagged yet.
:::

This release introduces explicit mutability, a unified function and closure syntax, first-class type hints with `is`/`switch` matching, and dedicated keywords for attributes and declarations. Together these changes significantly reshape the language surface from v0.0.1.

## Breaking Changes

- `module` keyword renamed to `mod`.
- `let` replaced by `const` (immutable) and `var` (mutable). Migrate existing `let` declarations to `const`.
- `func` keyword renamed to `fn`. Closures changed from `func name { args -> body }` and `{ args -> body }` to `fn name(args) { body }` and `fn(args) { body }`.

## Implemented Proposals

- [ZE-001 Base Language](/proposals/ZE-001-base-language) — Core language: declarations, expressions, operators, control flow, modules, imports, literals, and attributes.
- [ZE-002 The Cavefile](/proposals/ZE-002-the-cavefile) — Package manifest and task runner: `Cavefile` dependency declarations via the `cave` module (`@cave.Dependencies`, stdlib/local/git sources), and `@tasks.Exec`/`@tasks.Call` task declarations with typed flags/args wired into `zirric task run`/`x`.
- [ZE-013 Mutability and Constants](/proposals/ZE-013-mutability-and-constants) — Replace `let` with `const` and `var` for explicit mutability. Upvalue-based closure captures.
- [ZE-014 Attribute and Declaration Keywords](/proposals/ZE-014-attribute-and-declaration-keywords) — Dedicated `attr` keyword and mandatory parentheses for attribute application.
- [ZE-016 Unified Function and Closure Syntax](/proposals/ZE-016-closure-syntax) — Closures use `fn(params) { body }`, unifying named and anonymous function syntax.
- [ZE-017 Type Hints and Type Matching](/proposals/ZE-017-type-hints) — First-class type hints (`: T`, `-> T`), composite type expressions (`[T]`, `[K: V]`, `fn() -> R`), `is` type checking, and `switch` type matching.
- [ZE-008 Error Handling](/proposals/ZE-008-error-handling) — Standardized `Result` and `AnyResult` union types for failure-aware APIs in `prelude`.
- [ZE-009 Option Values](/proposals/ZE-009-option-values) — Standard `Optional` type for values that may be present or absent, defined in `prelude`.
- [ZE-018 I/O, Formatting, and OS](/proposals/ZE-018-io-fmt-os) — New `io`, `fmt`, and `os` standard library modules for byte streams, text formatting/printing, and OS interaction (stdout, stdin, stderr, exit, env, args).
- [ZE-010 Iterable](/proposals/ZE-010-iterable) — Custom `for element <- value` using `@Iterable` and adds `Range`, `ClosedRange`, `@Countable`, `Pair` types.
- [ZE-022 Static Checks](/proposals/ZE-022-static-checks) — Analysis reports mistakes it is certain about: undefined names, wrong arity, unsupported operators, unknown fields and members, and values that do not match the types a program declares. Amends ZE-017: a type hint that is written is now checked.

## Diagnostics

- Errors point at a line and column, and the CLI prints the line with a caret under it.
- Every problem in a file is reported at once, rather than one per run.
- A failure at runtime says where it happened and prints the stack that led there.
- Messages name types the way they are written — `String`, not `runtime.String` — and say which value they were given.
- An unclosed bracket is reported where it was opened.

## Bug Fixes

- Many compiler, virtual machine, and standard library fixes, most of them surfaced while writing the [ZE-020 Standard Library](/proposals/ZE-020-standard-library) modules in Zirric.
