# v0.2.0-next

::: callout warning Prerelease
This release is still in development and has not been tagged yet.
:::

A Zirric program still runs one thing at a time. What it can now do is wait on more than one of them: a key and a timer, a slow job and a user who presses `q`, several files handled as they become ready. Output gets easier to write on the way: a string literal can embed an expression, and `fmt` takes its writer first as the rest of the library does.

## Breaking Changes

- `fmt.fprint` and `fmt.fprintln` take the writer first: `fmt.fprintln(value, writer)` is now `fmt.fprintln(writer, value)`. Every other function that acts on a capability already took it first, and the `f` prefix promised this order to begin with. The migration is swapping two arguments, and the static checker reports the common call sites — a string where an `@io.Writer` is declared — before the program runs.

  ```zirric
  fmt.fprintln("Hello, Zirric!", os.stdout()) // before
  fmt.fprintln(os.stdout(), "Hello, Zirric!") // after
  ```

## Implemented Proposals

- [ZE-025 Routines and Channels](/proposals/ZE-025-routines-and-channels) — the [`co`](/stdlib/co) module: routines, the scopes that own them, and channels between them. No new syntax, no new keyword, no new operator.
- [ZE-032 String Interpolation](/proposals/ZE-032-string-interpolation) — a string literal may embed an expression as `\(expression)`, rendered exactly as `fmt.sprint` renders it.
- [ZE-034 Writer-First Printing](/proposals/ZE-034-writer-first-printing) — `fmt.fprint` and `fmt.fprintln` take the writer first, as everything else acting on a capability does.

## Notable Changes

- `zirric cave new` follows the created `Cavefile` with the commands and documentation links a new project needs next.
- `zirric ci forgejo` and `zirric ci github` write a workflow that checks formatting and runs the tests, installing the toolchain with [`setup-action`](https://code.knabel.dev/zirric-lang/setup-action).
- `zirric --help` sections its commands and the project's own tasks.

## Tooling

- [Tree-Sitter-Zirric](https://code.knabel.dev/zirric-lang/tree-sitter-zirric) is released under its own tags and does not yet know about `\( … )`. Until it does, an editor driven by it highlights an interpolation as part of the string around it. `zirric lsp` is not affected: hover, go-to-definition, completion and diagnostics all work inside one.

## Bug Fixes

- A closure written inside a `for` expression body can reach a variable of the enclosing function. The loop body has a symbol table of its own while running in the same frame, so such a reference was resolved against the frame's own captures — reporting an internal error, or silently reading an unrelated captured value when the indices happened to line up.
